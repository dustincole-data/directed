# Phase 1 review — the look gate

Decision this document supports: **build 83 more cells, or stop.**

Branch `phase-1`, 24 committed cells across 9 of the 48 declared rows: 9 Arm A baselines and 15 treated cells — 12 made with a named skill (all 9 Arm B cells plus 3 of the 6 Arm C cells) and 3 with a real tool loop. `verify-cells` clean, static build produces 25 pages. Every figure below was either measured directly against the committed `cells/**` files during this review or is cited from `.superpowers/sdd/2026-07-25-directed-phase1-plan/progress.md` (marked as such) — see the companion task report for which is which.

**Post-review addendum.** A final whole-branch review found that the integrity gate enforced less than this document, `README.md`, and `docs/factory.md` claimed, and that three published pages captioned a cell with a method it contradicts. The fix wave that closed those is recorded in `.superpowers/sdd/2026-07-25-directed-phase1-plan/final-fix-report.md`; every claim below is current as of that wave, including the test count (**115 tests green**, up from 91) and §7's recommendation list.

## 1. Verdict

- **Worth continuing, with one process fix.** When a row's stated lever is actually exercised, the difference is large, exact, and independently verifiable down to the hex code — this is not a subjective "looks nicer" gallery, it's a measurement instrument.
- **3 of the 15 treated cells didn't test what they claim to — 20% of treated cells, 12.5% of the 24 committed ones.** `mark-07-overlap.B` and `mark-07-overlap.C` — both its treated arms, not one — ship circle positions and opacity byte-identical to Arm A; `type-04-numerals.B` (tabular vs. proportional figures) never touched numeral formatting. Full cell-by-cell table in §4. All still "pass" the integrity gate because the gate checks structure and provenance, not whether the row's claim was tested.
- **The machinery is real and enforced — after the fix wave, on all three files in a cell.** Immutability + the `chart.js` hash held under adversarial review (Task 8, 10), but the final review defeated the guarantee 11 ways through the two files it did not cover: the gate now also re-renders every cell and byte-compares against the committed `render.svg` (the artifact the gallery actually publishes), and cross-validates every `cell.json` field against `src/rows.json`, the directory the cell lives at, and `chart.js`'s own hash-verified `meta`. The craft module techniques (per-datum gradient, spectral field) are verifiably wired, not decorative. The one from-scratch row (`mark-01-glyph`) shows three genuinely different construction strategies, not just three color choices.
- **The Arm C screenshot-diff loop over-delivered.** Both screenshot-diff rows independently found and fixed a real label-collision bug in the Arm A baseline — evidence the loop does more than cosmetic conformance.
- **The gallery shell has no visual design pass yet.** `src/styles/gallery.css` is 38 lines: it self-hosts Archivo 400/600 via `@font-face`, defines a four-token palette (`#fdfdfc` / `#16161a` / `#6b6b73` / `#e4e4e8`), and lays out an `auto-fit` responsive grid — a competent floor, and nothing beyond it. That's in-scope for Phase 1 per the spec (shell design isn't a Phase 1 deliverable), but expect the screenshots below to read as a spreadsheet, not a gallery, until that pass happens.

**Count: 3 of 24 committed cells (3 of 15 treated cells, 20%) have a genuinely untested premise** — `type-04-numerals.B`, `mark-07-overlap.B`, `mark-07-overlap.C` — spanning 2 of the 9 rows. `mark-07-overlap` is not "a row with a weak comparison": it misses its stated premise on **both** of its treated arms, 2 for 2.

- **`mark-02-gradient`'s baseline used gradients unprompted, in the shipped run.** Arm A's median run already ships 8 off-centre per-datum radial gradients (`cx=38% cy=32% r=72%`) — a `hero8-sun` sun gradient and 8 planet gradients, each with its own 3-stop color ramp, each circle correctly referencing its own gradient via `fill="url(#...)"`. This is not a flat-fill baseline. (Whether all 3 discarded Arm A runs did this, not just the shipped one, is a ledger-only claim — not independently checkable from committed artifacts.)
- **The integrity gate does not catch any of the 3 untested-premise cells.** `verify-cells.mjs`'s checks are structural and provenance-level — files exist; the prompt is non-empty, placeholder-free, and contains the artifact the arm was sent; `chart.js`'s hash matches; `render.svg` re-renders byte-identically; every manifest field agrees with `src/rows.json`, the cell's directory, and `chart.js`'s `meta`; run counts follow the anti-cherry-picking rule; lineage resolves; gap rows carry no treated cell. None of them ask "did this cell change what the row claims to test." This hole existed through all of Phase 1 undetected by any automated check or generation-time review, and was only caught at final gate review (see §7 recommendation 1).

## 5. Honesty ledger

- **`mark-02-gradient` Arm B took 3 generation attempts.** Attempts 1–2 failed on harness/brief defects (an unresolvable extensionless import path, then a raw DOM element passed where the craft helper needed a d3 selection) — not on aesthetic grounds, and no attempt was compared against another to pick a favorite. Disclosed verbatim in the cell's `notes`.
- **`color-03-diverging` Arm C's notes originally carried a false claim** ("not borrowed from this project") when its entire lever *is* this project's `src/craft/spectral.ts`. Caught and corrected during Task 16 review; current notes are accurate.
- **Three cell pages captioned a cell with a method it contradicts.** `armLabel()` derived the caption from the arm letter, so `color-01-categorical.C`, `color-03-diverging.C`, and `mark-07-overlap.C` each published "C · with a tool" directly above its own `skill` method chip — and a passing test pinned that mapping. Caught at final review and fixed in the fix wave; the caption now comes from the cell's recorded `method.kind`. `src/rows.json` declares 11 of the 107 cells in that shape (6 Arm C skills, 5 Arm B tools), so the same defect would have reached 11 pages.
- **Model: `claude-sonnet` for every arm, every cell** — confirmed above. The comparison isolates *method* (default prompt vs. named skill vs. tool loop), not model.
- **Deviation from the brief:** the task brief said to save screenshots to the scratchpad; they were committed to `docs/screenshots/` instead so the relative links in this doc actually resolve for anyone reading it from the repo. Named here per this project's convention of flagging every deviation, not silently taking the better path.
- Standing disclosures — global-CLAUDE.md baseline contamination (Arm A is naive about *this project*, not naive about design in general), the permitted post-generation edits, refine-vs-from-scratch, gap rows, and the nine refuted research claims — are all in `docs/method-draft.md` and are not repeated here. Nothing in this document contradicts that file.

## 6. Cost, extrapolated

**Measured for Phase 1** (from `progress.md`, cross-checked against the commit history): 9 rows, 24 shipped cells required **44 generation-agent invocations** —
- Arm A: 27 (9 rows × 3 runs each, the fixed methodology, not a retry count)
- Arm B: 11 (9 rows × 1 run, plus 2 extra attempts on `mark-02-gradient`'s harness-defect retries)
- Arm C: 6 (the 6 of the 9 rows that declare an Arm C × 1 run; 2 of those — `type-01-typeface.C` and `type-02-scale.C` — ran real screenshot-compare-fix loops of **3 iterations each** (that's the metric that matters: one implement→screenshot→compare→fix cycle, repeated 3 times, before the result shipped). Tool-call counts for those loops (27 and 31 respectively) are supporting color, not the iteration count, and cost *inside* one agent invocation, not extra agents.

**Phase 2 is 39 more rows, 83 more cells** (39 Arm A, 38 Arm B, 6 Arm C — confirmed from `src/rows.json` via the registry, exactly matching the spec's 107-cell/48-row total). One caveat the spec doesn't carry: `rows.json` marks 6 of those 83 (`lib-01-ceiling`, `lib-02-anchored`) as `phase: 3`, so 77 cells are Phase 2 proper and 6 are deliberately held back — `lib-01-ceiling` is blocked on the `cells/_contract.md` d3 problem in recommendation 2. Applying Phase 1's fixed methodology mechanically: 39×3 (A) + 38×1 (B) + 6×1 (C) = **161 generation-agent invocations minimum**, before any retries. Phase 1 saw one row need 2 extra retries out of 9 Arm B rows (~22%); if that rate holds, expect Phase 2 to land closer to **180–190 invocations**. This is an **estimate**, not a measurement — the ledger records tool-call counts and agent counts, not wall-clock time or token spend, so no dollar or time figure is given here; inventing one would violate the "don't invent numbers" constraint on this task. The "proven machinery" only removes *wiring* overhead (render/register/verify), not generation-agent count — each cell still needs its own real run.

## 7. Recommendations before Phase 2

1. **Add a premise-engagement check to the gate, before Phase 2.** The gate has never checked that a treated arm differs from its baseline at all, let alone in the dimension the row claims to demonstrate — nothing in `verify-cells.mjs` compares a treated arm to its Arm A. (An earlier draft of this line said such a check existed; it did not, and §4 above described the situation correctly. The "no cell is code-identical to its baseline" figure in §3 was a manual measurement made during this review, not gate output.) That gap existed through all of Phase 1 undetected and was only caught at final review, on 3 of 24 cells (§4). Check per row, not just per build, before a cell is marked done.
2. Fix `cells/_contract.md`'s line 12 ("or a d3 selection over it") before generating `lib-01-ceiling` — it names d3 to the naive Arm A baseline in the one row where library choice is the entire subject, contaminating the exact thing that row measures (already flagged in `docs/method-draft.md`). Do **not** edit the contract on the `phase-1` branch: 24 shipped cells quote it in their published prompts, so changing it now would make their disclosure reference text that no longer exists. `lib-01-ceiling` is `phase: 3`, so none of Phase 2's 77 cells is affected.
3. **Do this first in Phase 2, before any new cells:** add a typecheck gate. `npx tsc --noEmit` fails with **16 errors** today — 8 unresolvable module types (`@types/node` for `node:fs` in `docs/docs.test.ts`, plus `@types/jsdom`, `@types/d3-selection`, `@types/d3-color`), 5 implicit-`any` parameters in `src/craft/gradient.{ts,test.ts}` and `spectral.{ts,test.ts}`, `src/rows.ts:28`'s readonly/mutable mismatch, and `src/scaffold.test.ts:12`'s string index into a literal-typed object. (An earlier draft said "~15" and the final review said 19; both were wrong — the figure is 16, re-measured with `.astro/types.d.ts` present.) Nothing blocks the build because Astro/Vite don't typecheck, which is why it isn't a merge blocker — but 83 more cells' worth of new code will compound it silently.
4. Extend the gap-row test coverage (currently only exercises `mark-04-glow`) to `mark-05-texture` and `legend-03-art` before Phase 2 ships them as gap rows — same code path, untested for 2 of the 3 cases that will actually use it.
5. Fix `render-cell.mjs`'s silent 640×400 fallback when `meta.width`/`meta.height` is omitted, and add cell-directory context to its error output — with 83 more renders queued, a silently-wrong-sized cell is easy to miss.
6. ~~Document the row-id regex and correct the `--row-title`/`--family` claim.~~ **Done in the final fix wave:** `docs/factory.md` now gives the regex, the flags apply only to an undeclared row, `new-cell.mjs` rejects a pair that contradicts a declared row, and the gate compares every manifest's `rowTitle`/`family` against `rows.json`.
7. Decide the dependency question at the Phase 2 bump and record it. `npm audit` is now **7 vulnerabilities — 3 moderate, 3 high, 1 critical** (worse than the 7 deferred at Task 1, which had no critical). Critical is `vitest`/`@vitest/mocker` (arbitrary file read+execute while the Vitest UI server is listening; the UI is not used here); highs are the `astro` XSS set, `sharp`/libvips, and a `vite` Windows path traversal. `npm audit --omit=dev` reports **0** — every one of them is dev/build-time or an SSR feature this static site does not use, and the only remediation is the breaking `astro@7`.
8. Budget a visual design pass on `src/styles/gallery.css` (38 lines: self-hosted Archivo, a four-token palette, one responsive grid) before this ships publicly — correctly out of scope for Phase 1's machinery-first goal, but the gallery reads as a data table, not a showcase.
9. **When this repo gets a git remote, add the CI workflow.** There is none today, and no pre-commit hook: the gate's enforcement points are `npm run build` (which runs `verify:cells` first, including on the deploy build) and running `npm run verify:cells` by hand. The spec's §8/§13 claim of CI + pre-commit enforcement has been corrected to say that.
